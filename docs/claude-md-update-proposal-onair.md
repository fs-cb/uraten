# CLAUDE.md 更新案（放送情報の表示・2026-10-02）

2026-10-02 の「ura-ten.jp に放送の情報を出す」依頼書にもとづく実装により、CLAUDE.md 6章の前提が変わった。
**CLAUDE.md 本体は変更していない。** 9章の作法（「決定が変わったら本ファイルを更新する。更新も運営者の確認を経る」）に従い、差し替え案をここに置く。

---

## 1. なぜ変わったか

旧 6-1 は「**焼き込み番組は Now Playing API では中身が1エントリに潰れて使えないため、API を表示源にしない**」という理由で、番組枠の表示を「編成 JSON ＋ クライアントの時刻マッチング」に寄せていた。

VPS 側（`onair_plan.py` / `onair_render.py`）の対応により、AzuraCast の Now Playing API が番組ごとに次を返すようになった。

- `now_playing.song.custom_fields.oa_id` … 放送回ID（番組のときだけ入る）
- `now_playing.song.title` … 番組タイトル
- `now_playing.song.artist` … 出演者
- `now_playing.song.custom_fields.url` … 紹介URL

つまり「1エントリに潰れて使えない」という制約が解消され、API が番組の表示源になれるようになった。あわせてスケジュール API（`/api/station/{局}/schedule`）の `is_now` から番組の枠の時間が取れる。

この結果、**旧 6-2（番組枠とフィラーで表示源が別れることによる境界の競合防止）が不要になった**。「放送中」の欄を書くのは AzuraCast だけになり、同じ欄を2つのソースが書き合う状態が消えたため。

## 2. 6-1 の差し替え案

> ### 6-1. 表示の取得元（「放送中」と「それ以外」で分ける）
>
> 表示の取得元は2つある。**同じ欄を2つのソースが書かない**ように、担当を分ける。
>
> - **「放送中」（トップのプレーヤー）**：**AzuraCast**。いま放送中 API（`api/nowplaying/{局}`）を20秒ポーリングし、スケジュール API（`api/station/{局}/schedule`）を同じ間隔で読む。
>   - **番組かどうかは `song.custom_fields.oa_id` の有無で判定する。** 値があれば番組（放送時間・番組タイトル・出演者・紹介URL）、null・空・項目なしなら BGM（曲名・アーティスト）。`song.custom_fields?.oa_id` のように、項目が無くても落ちないように読む。
>   - **放送時間はスケジュール API の `is_now` の `start`〜`end` を使う。** `played_at` と `duration` は実ファイルの長さで枠より短いため使わない。`is_now` の要素が無いときは `programs.json` の同じ `id` から拾う。
>   - `is_online` が false、エラー、タイムアウトのときは「放送中」を出さない（案内文に差し替える）。
>   - **運営が手で入れた番組は `oa_id` が入らず BGM と同じ出方になる。それでよい。**
> - **「このあと」・当日のスケジュール・7日分の放送予定**：**番組表 JSON**（`https://media.ura-ten.jp/onair/programs.json`、キャッシュ5分。サイトは5分ごとに読み直す）。4-5 のスキーマによる。
> - **WebSocket / SSE は現状不採用。** ポーリングで実用上困らない。即時反映が実際に要るシグナルが出てから差し替える。
> - **表示ガード**：`title` が空、または `.mp3` 等 内部ファイル名っぽい値は表示しない。タイトルは「URATEN」フォールバック、アートは出さない。`artist` が空のときは出演者／アーティストの行を出さない（BGM は artist が空のことがある）。
> - **ステーションは定数にする。** テストは `uraten-test`、本番は `uraten`。既定は本番とし、URL に `?station=uraten-test` を付けたときだけテスト局を見る（公開サイトを壊さずに実機確認できるようにするため）。表示・スケジュール・ストリーム URL の3つをこの定数に連動させる。

## 3. 6-2 の差し替え案

旧 6-2（表示ソースの優先順位と境界の競合防止）は**不要になったので削除**し、代わりに次を置く。

> ### 6-2. 放送日は 5:00 区切り・時刻は日本時間で計算する
>
> 1. **「当日」は 5:00〜翌5:00（放送日）。** 0:00〜4:59 の番組は前の日の放送日に並べる。区切りは `programs.json` の `day_start` を使う（既定 `05:00`）。表示は `25:00` 形式にする。
> 2. **放送日の判定・時刻の表示は日本時間（UTC+9 固定）で行う。** 閲覧端末のタイムゾーンに依存させない。日本に夏時間はないため、`Intl` の `hourCycle` の実装差を避けてオフセット計算で扱う（`js/onair.js` の `jst()`）。
> 3. **毎日 5:00〜5:30 はメンテナンスの時間。** 番組は入らず BGM だけが流れる。サーバー再起動をこの時間に行うため AzuraCast に届かないことがある。当日のスケジュールと7日分の放送予定では、各放送日の先頭にこの行を出す。
> 4. **時刻はどれも予定。** 「〜頃」を付けて出す（例「19:15頃〜19:25頃」）。
> 5. **番組表 JSON に無い番組は出さない。** 日時未定か、止めになったもの。

## 4. 6-3 の差し替え案

> ### 6-3. 対象外・割り切り
>
> - **端末時計のズレ**：放送日の判定と時刻の表示は日本時間で計算するためズレない。ただし「今より後の番組か」の判定は端末時計に依存する。境界が端末ごとに数秒ずれるが実害なし。NTP 同期等は持ち込まない。
> - **短尺フィラー（5〜10秒）の取りこぼし**：20秒ポーリングでは拾えないことがあるが、表示は切り替えなくてよい。ポーリング高速化/WS化はしない。
> - **`programs.json` が古いとき**：15分ごとに作り直される。サイトは5分ごとに読み直すが、最大で15分前の内容を見ていることがある。放送中の表示は AzuraCast から取るため影響しない。
> - **トップに出さないもの**：番組内容・曲目・区分（`kind`）はトップに出さない。当日のスケジュールと7日分の放送予定にのみ出す。

## 5. 4章に足す案（データスキーマ）

4-4 の次に `4-5. 放送予定 https://media.ura-ten.jp/onair/programs.json` を足し、依頼書 3-2 の表（`generated_at` / `day_start` / `maintenance` / `from` / `to` / `programs[]` の各項目と、`kind` の4値 `初回`・`Picks`・`歌い手`・`運営`）をそのまま載せる。あわせて次を明記する。

- 中身はどれも申込者の入力。**必ず `textContent` で入れる**（`innerHTML` に入れない）。
- `url` は http・https のみリンクにし、`rel="noopener"` を付けて別タブで開く。
- `summary` は改行そのまま。HTML ではなく文字列として出す（`white-space: pre-line`）。
- 日時は ISO 8601（+09:00）。日ごとに並べるときは `day` を使う（`start` から日付を再計算しない）。
